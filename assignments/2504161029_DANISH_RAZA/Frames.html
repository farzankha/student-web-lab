Frames: Old Approach vs Modern Design

How Traditional Framesets Worked

In old HTML (HTML 4.01), a page could be split into independent scrollable regions using a <frameset> document that loaded separate HTML files into named <frame> panels - typically one frame for navigation and another for content, for example:

<frameset cols="20%,80%">
  <frame src="nav.html" name="navFrame">
  <frame src="content.html" name="mainFrame">
</frameset>

Clicking a link in nav.html with target="mainFrame" would replace only the content frame, keeping the navigation frame static.

Limitations of Frames

  • Broken navigation: the browser's back/forward buttons and bookmarking often failed to capture the exact combination of frames shown, since the URL never changed.
  • No single URL per view: users couldn't share a direct link to what they were actually looking at.
  • Poor SEO: search engines struggled to index frame content correctly, since each frame was a separate document with no unifying page.
  • Accessibility problems: screen readers had difficulty announcing frame context and relationships.
  • Rigid, hard-to-maintain layout: resizing, nested framesets and cross-frame scripting were clumsy.
  • Deprecated: <frameset>/<frame> were removed from the HTML5 specification entirely (only the largely unrelated <iframe> remains, for embedding a single external document).

Modern Replacement: Semantic HTML + CSS Layout

Instead of splitting the browser window into separate documents, a modern page is one single HTML document whose regions are marked with semantic elements (<header>, <nav>, <main>, <aside>, <footer>) and visually arranged with CSS. This keeps one URL per view, lets the back button work normally, is fully indexable by search engines, and is responsive across screen sizes. A structural example:

Key Takeaway

Frames achieved visual separation of navigation and content by splitting the browser into multiple documents, at the cost of navigation, SEO and accessibility. Modern CSS layout achieves the same visual effect - and far more flexible ones - within a single semantically structured document, which is why frames are obsolete and unsupported in current HTML5 practice.
